## Review

- Correct: Protocol routing is coherent: each provider has a distinct endpoint/API mapping (`src/catalog.ts:6-32`), endpoint precedence and ID deduplication are implemented centrally (`src/catalog.ts:145-157`), request base URLs match the three adapters, and live isolated requests reportedly passed.
- Correct: Catalog prices and limits override built-in metadata, output limits are clamped to context size, and cache writes use a temporary file plus atomic rename with mode `0600` (`src/catalog.ts:105-132`, `src/index.ts:39-49`).
- Correct: Refresh failures do not overwrite `current`; successful fetches update it only after parsing/projection, while cache-write failures are intentionally non-fatal (`src/index.ts:75-86`).

- Finding: **P1 — Removed models cannot disappear during dynamic refresh.** Each provider registers its startup catalog as the immutable `models` baseline (`src/index.ts:101-102`, `src/index.ts:131`). Pi’s `createProvider` merges refreshed models over that baseline rather than replacing it (`node_modules/@earendil-works/pi-ai/dist/models.js:428-440`). Consequently, if Aperture later removes a startup model or drops its supported endpoint, refresh returns a list without it but the baseline keeps it available for the life of the extension. Register providers with an empty baseline and publish the initial catalog through replaceable dynamic state, or otherwise use provider state whose catalog is fully replaceable. Add a refresh test covering removal and endpoint migration.

- Finding: **P1 — The default test command is not reproducible in a clean checkout/package.** `npm test` always runs `test/catalog.test.ts`, whose final test unconditionally reads `/tmp/aperture-models.json` unless `APERTURE_FIXTURE` is set (`test/catalog.test.ts:72-80`). That file is neither packaged nor generated by the test script, and the README runs `npm run validate` before the command that downloads it (`README.md:25-30`). Validation therefore fails with `ENOENT` on a clean machine despite being the documented verification path. Commit a deterministic fixture or make the live-fixture test explicitly opt-in/skipped when no fixture is configured.

- Finding: **P2 — Authentication documentation contradicts actual wire behavior.** The README says the extension “deliberately does not synthesize an `Authorization` header” (`README.md:19-22`), but ambient Tailscale auth explicitly returns `headers: { authorization: "Tailscale" }` (`src/index.ts:112-126`). Document that non-secret marker header accurately, or change the implementation if sending no authorization header is the intended contract.

- Finding: **P2 — Runtime/cache/auth behavior has no automated coverage.** Existing tests exercise only catalog parsing/projection and route uniqueness (`test/catalog.test.ts:20-69`); none import or instantiate `src/index.ts`. Startup network failure with cache fallback, malformed cache handling, cache-write failure, coalesced concurrent refresh, abort propagation, stale-model removal, no-network refresh, and ambient/API-key auth resolution are untested. Focused provider-level tests with mocked `fetch`, temporary `XDG_CACHE_HOME`, and a fake `ExtensionAPI` would cover the highest-risk semantics without live services.

- Merge verdict: **BLOCK** until the non-removable startup catalog and clean-test failure are addressed.
